# 천라지망 AI — 실시간 수색 범위 추천을 위한 학습 설계

이 문서는 **학습 착수 전에 작성한 설계 기록**이다. 2026-09-19 실제 발견 거리·수색대 속도 학습과 앱 계획 연결을 진행했다. 현재 구현 및 남은 범위는 [실제 학습 결과와 사용법](AI-학습결과와-사용법.md)을 따른다. 아래 단계별 미구현 표현은 최초 설계 당시 상태다.

## 1. 목표를 정확히 정의하기

목표는 ‘실종자의 위치 한 점을 맞히기’가 아니라 **현재까지의 근거와 가용 인원으로 다음 일정 시간에 수색할 구역·우선순위·예상 투입시간을 제안하기**이다. 첫 동작 예시는 ‘3개 팀, 다음 30분’처럼 사람이 지정한 예산이다. 이는 예시 조건이며 실제 인원·시간을 가정해 넣지 않는다.

프로그램 이름은 **천라지망(天羅地網)**, 추천·예측 모듈 이름은 **천라지망 AI**로 한다. 수색 대상은 위험에 처한 사람을 돕는 것이므로 홍보·화면 문구에는 ‘포획·도망갈 곳 없음’보다 ‘놓친 구역을 줄이고 근거를 남기는 수색’의 의미를 사용한다.

실시간 추천은 학습된 모델로 새 입력을 계산하는 **추론**이다. 실제 수색 중 미확인 제보·불완전한 GPS로 모델 가중치를 자동 재학습하지 않는다. 재학습은 별도 검증된 자료로 수행하고 승인된 모델 버전을 배포한다.

## 2. 예측과 계획을 분리한다

```text
마지막 확인 위치·시각 + 지형·도로·시설 + 검증 가능한 관측
                         ↓
            이동/위치 모델: 시각별 후보 위치분포
                         ↓
           승인된 미발견 증거와 시각에 맞춰 갱신
                         ↓
     수색 계획기: 팀 위치·인원·남은 시간·탐지 가정·접근 제한
                         ↓
            후보 구역·경로·투입시간·변경 이유 제안
                         ↓
                   조정자가 배정 확정
```

확률이 가장 높은 구역이 항상 가장 좋은 수색 구역은 아니다. 도착까지 오래 걸리거나 일반팀이 접근할 수 없을 수 있다. 반대로 낮은 확률이라는 이유만으로 미수색 구역을 ‘사람 없음’으로 확정할 수 없다.

현재 앱은 30 m 계산 격자와 480 m 표시 구역, 승인된 미발견 반영, 시간 추정·가정 기반 순위가 있다. 아직 인원·시간에 맞춘 수색 경로 최적화나 학습된 구역 선택 정책은 없다. **수색자 속도 모델은 계획기의 예상 소요시간을 돕는 보조 모델**이다.

## 3. 무엇으로 학습할 수 있나

| 확보 자료 | 지금 배울 수 있는 것 | 배웠다고 말할 수 없는 것 |
|---|---|---|
| 실종 하이커 65건의 마지막 위치·발견점 | 선택된 표본의 발견점 거리분포 기준 모델 | 시각별 실종자 경로·현재 위치확률·한국 전체 실종 행동 |
| 수색대 61 GPS 트랙 | 수색대 속도와 경사·방식의 관계 | 실종자 속도·밤 행동·POD |
| 훈련 1회 9명 GPS | 기록 처리·중복 경로·팀 움직임 검사 | 독립 실종 사건 9건 또는 실제 수색 성능 |

파일·출처는 [공개 자료 안내](../data/research/README.md)에 있다. 65건에는 실제 경과시간이 없고, 61트랙에는 절대시각이 제거돼 있다. 누락 값을 기사나 수집 시각으로 추측해 채우지 않는다. 전체 수색 이력·시각별 제보·탐지 성패와 최적 구역 정답은 확보하지 못했다.

## 4. 권장 학습 순서

### 단계 A — 위치분포의 작은 기준 모델

먼저 `incident_endpoints.csv`의 실제 사건만 사용한다. 원본 해시와 사건별 평가 분할을 고정한 뒤, 훈련 사건의 마지막 위치→발견 거리 분포를 적합한다. 로그정규 거리분포 같은 적은 수의 매개변수 모델부터 비교한다. 발견점으로 계산한 거리·방향은 **학습 타깃/평가값**이며 같은 사건의 예측 입력이 아니다.

65개라는 수 자체가 복잡한 모델 학습을 불가능하게 하는 절대 기준은 아니지만, 다양한 지형·시간·개인 특성을 학습했다고 주장하기에는 현재의 특성과 표본 범위가 부족하다. 사건을 하나씩 빼거나 사건 단위 교차검증을 하고, 범위를 좁혀 명시한다. 좌표가 가까운 사례가 섞이는 공간 누출도 점검한다.

이 모델은 발견점 기준 모델이지 특정 시각의 실제 존재분포가 아니다. 현재의 시간 모형에 즉시 교체하지 않고 **오프라인 평가/별도 비교 모드**에 먼저 둔다. 지형을 조건으로 적합하려면 미국 사건 각각의 실제 지역 지형 자료를 확보해야 하며 제주 지형을 적용하지 않는다. 원 논문의 사후 적합 파라미터·모의 결과는 해당 사건의 독립 정답으로 재사용하지 않는다.

### 단계 B — 시각별 이동 모델용 정답 확보

다음처럼 **시각이 있는 궤적**이 있어야 ‘지금 어디 있을까’를 직접 학습할 수 있다.

```text
episode_id, participant_pseudonym, observed_at_with_timezone,
lat, lon, gps_accuracy_m, terrain_slope, landcover,
road_distance, facility_access_cost, light_condition,
movement_state, label_source
```

- 정해진 시간 간격으로 정렬하되 GPS 공백을 직선 이동 정답으로 메우지 않는다.
- 입력은 예측 시점에 실제로 이용 가능한 과거 상태와 지형이다. 이후 발견점·이후 트랙은 타깃에만 쓴다.
- 첫 모델 후보는 이동/정지 분류 + 이동속도 회귀 + 후보 방향별 점수다. 작은 트리 모델부터 기본 이동규칙과 비교한다. 방향 점수를 확률로 사용할 때는 별도 보정 평가가 필요하다.
- 안전한 허가 코스의 동의된 보행 훈련은 개발·시험에 사용할 수 있지만 실제 실종자의 행동 정답을 대신하지 않는다. 위험한 야간 산행·의도적인 실제 조난은 만들지 않는다.
- 실제 익명 사건 자료의 적법한 이용·접근은 기관 협력이 별도 필요하다. 이번 작업은 기관 문의나 데이터 전송을 하지 않는다.

정답 확보 전에는 기존 지형 이동 시뮬레이션을 명시적 가정으로 사용한다. 밤에 60%로 느려지도록 만든 시뮬레이션을 학습한 뒤 ‘실제로 밤이면 60%’라고 검증한 것으로 발표하면 안 된다.

### 단계 C — 수색 계획기를 먼저 기준 알고리즘으로 구현

위치 모형과 별도로, 후보 행동을 `팀 + 구역/경로 + 수색시간`으로 정의한다. 다음은 초기 비교용 근사 점수다.

```text
행동 가치 ≈ 그 행동으로 추가 발견할 것으로 기대되는 확률 / 소요시간
소요시간 = 도착까지의 이동 + 실제 수색
```

위험·전문기관 전용·미승인 접근은 먼저 일반팀 후보에서 제외한다. 높은 확률로 위험을 상쇄시키지 않는다. 위험 구역의 존재확률 자체는 지우지 않는다.

발견효과는 셀별 위치 질량과 계획한 탐지 강도를 이용한다. 팀이 도착하기 전에 실종자가 이동할 수 있으므로 현재 지도 한 장 대신 도착/수색 시점의 예측 분포를 사용한다. 짧은 계획 구간의 근사에서 시작하고 그 한계를 표시한다.

중복 경로는 추가 발견효과만 평가해야 한다. 두 팀이 같은 구역을 돌 때 첫 팀의 효과를 두 번 더하지 않는다. 아직 실행하지 않은 추천을 미발견 증거로 반영하지 않는다. 탐지율이 검증 전이면 결과도 가정별 범위로 비교한다.

첫 버전은 위험 제한을 적용한 탐욕적 선택·시간 예산 배정으로 기준을 만들고, 이후 OR-Tools 같은 제약 최적화 도구와 비교한다. 이 부분은 반드시 신경망으로 학습해야 하는 문제가 아니다. 제약 최적화도 자동 추천 기능을 구현할 수 있지만 이를 ‘실제 사건으로 학습한 AI’라고 표현하지 않는다.

### 단계 D — 구역 선택 정책 학습은 그다음

강화학습은 후속 연구 후보이지 첫 필수 단계가 아니다. 적용한다면 아래를 모두 갖춰야 한다.

- 상태: 시스템이 볼 수 있는 확률지도·수색 이력·팀 상태·시간만. 숨겨 둔 표식/실종자 정답 위치를 모델 입력에 넣지 않는다.
- 행동: 안전·접근 제한을 통과한 후보 구역/경로 배정.
- 보상: 모의 발견까지 걸린 시간과 투입 비용 등 사전 정의된 목표. 위험은 보상 감점에만 맡기지 말고 행동 자체를 제한한다.
- 훈련 환경: 여러 이동 가설·탐지율·GPS 오류·제보 지연을 바꾼 모의 환경. 최적화 결과를 모방하면 ‘계획기 모방 학습’이며 실제 행동 학습이 아니다.
- 평가 환경: 지도·회차·시드뿐 아니라 정답 생성 규칙도 분리한다. 같은 생성기로 학습·평가한 성공을 실제 수색 성능이라고 말하지 않는다.

현장 로그에서 추천한 구역에 사람이 있었는지 확인되지 않았다고 해서 ‘오답’ 라벨을 주면 안 된다. 수색하지 않은 구역도 정답을 알 수 없다. 발견점 하나는 ‘그전에 어느 구역을 선택했어야 했는가’의 완전한 정답이 아니다.

## 5. 실시간 연결과 승인

일정 간격(현재 화면은 약 15초 갱신) 또는 승인된 수색 결과가 생길 때 새 추론을 요청한다. 갱신 간격은 계산 예산이며 성능 SLA가 아니다. AI 학습은 이 실시간 경로 밖에 둔다.

현재 GPX 업로드는 이동 기록일 뿐이다. 조정자의 **완료·미발견 승인**을 거쳐야 음성증거로 쓴다. 미확인 단서는 장부와 채택/미채택 시나리오로 유지하고 임의의 신뢰점수로 지도를 옮기지 않는다. 동적인 관측 갱신은 관측 시각과 이동 순서를 맞춰 재생해야 한다. 현재의 승인 시각 스냅샷만으로 완전한 시계열 필터를 구현했다고 말하지 않는다.

다음 인터페이스는 **제안**이며 아직 API에 추가하지 않았다.

```text
입력: mission_id, base_version, as_of, model_version,
      team_locations, capabilities, available_minutes, access_constraints
출력: proposal_id, input_hash, generated_at, expires_at,
      suggested_sectors, suggested_routes, expected_minutes,
      assumption_ranges, change_reasons, status=PROPOSED
```

계획은 기존 확정 배정을 자동 덮어쓰지 않는다. 새 추천과 확정 배정을 분리하고, 지도가 약간 바뀔 때마다 팀을 되돌리지 않도록 최소 유지시간·변경 폭 규칙을 검증한다. 입력 버전이 오래되었으면 승인을 거부하고 다시 계산한다. 작업 실패·시간 초과 시 마지막 제안에 오래됨 경고를 붙이고 확정 배정은 유지한다.

AI가 후보 범위를 자동 결정할 수는 있지만 **실제 팀 배정·위험 지역 진입·수색 종료는 현장 책임자가 확정**한다. 앱은 안전필수 통신 채널이 아니다.

## 6. 무엇으로 성공을 평가할까

| 층 | 평가 | 반드시 비교할 기준 |
|---|---|---|
| 위치 분포 | 보지 않은 사건의 로그 점수, 동일 면적 적중률, 구역 확률 보정 | 균일/거리/기존 지형 모형 |
| 수색 정책 | 같은 인원·시간에서 발견율/발견시간, 중복·미수색 면적 | 거리순/현재 우선순위/탐욕 계획기 |
| 안전·운영 | 위험 추천 차단, 버전 불일치 차단, 지연·실패 처리 | 기존 승인 절차 불변 |

사건·사람·회차 단위로 자료를 나눈다. 같은 트랙의 인접 점을 훈련과 시험에 무작위로 섞지 않는다. 전처리·튜닝도 훈련 묶음 안에서만 한다. 가정 범위를 통계적 신뢰구간으로 부르지 않는다.

실패·미발견 회차도 보고하고 종료 시점까지 못 찾은 결과를 통계에서 빼지 않는다. 모의 실험과 실제 사건 평가를 분리한다. 공개 65건만으로 시간별 위치 성능·수색시간 단축을 직접 평가할 수는 없다.

## 7. 실제 개발 산출물 순서

1. **자료·평가 고정:** 원본 해시, 사건 분할, 제외 규칙, 평가 구역과 지표를 파일로 기록.
2. **발견점 기준 모델:** 65건의 작은 공간 통계 모델과 보지 않은 사건별 평가 결과. 파일 이름에 `endpoint_baseline`을 붙여 실시간 경로 모델과 구분.
3. **계획기:** 기존 가정 분포를 받아 인원·시간·접근 제한으로 후보 구역을 선택. 단순 기준과 비교.
4. **이동 학습:** 시각별 정답 자료가 확보된 뒤 이동/정지·속도·방향 모델을 별도로 학습하고 검사.
5. **앱 비교 모드:** 기존 가정 모델과 학습 모델을 나란히 보여 준다. 기존 임무는 모델 버전을 고정한다.
6. **감독 훈련:** 숨긴 표식과 블라인드 조건으로 도구의 도움 여부를 검증한 다음 현장 사용 범위를 논의.

처음 도구는 Python·NumPy/SciPy·scikit-learn과 CPU로 제한된 실험을 시작한다. 복잡한 신경망·GPU·강화학습은 데이터와 비교 결과가 필요성을 보여 준 뒤 검토한다. 모델 설명(model card)에 학습 자료 범위·코드/모델 해시·사용 특성·평가 결과·미검증 항목을 남긴다.
