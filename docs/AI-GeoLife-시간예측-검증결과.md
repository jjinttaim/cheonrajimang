# 천라지망 — 시간이 지난 뒤 위치 분포의 추가 검사

2026-09-20. **실제 진척이지만 전체 목표 완료는 아니다.** 기존 모델을 바꾸지 않고, 다음 30초 속도·회전의 맞음 정도를 넘어 2분·5분 뒤 위치 분포가 실제 도착점을 어떻게 포함하는지 검사했다. [사전 고정 계획](AI-GeoLife-시간예측-검증계획.md).

## 무엇을 실행했나

- 기존 v1 모델 `a0d0ebfd…`와 사람별 분할을 동결했다. 재학습, 가짜 궤적을 정답으로 쓰기, 채택 기준 완화는 하지 않았다.
- 기존 최종 평가 사람 5명에게서 끊기지 않은 5분 기록 **214구간**을 구성했다. 사람별 구간 수는 52, 30, 7, 89, 36이다. 같은 사람의 여러 구간을 독립된 사람으로 세지 않았다.
- 앱 실험실과 같은 조건인 **출발 위치만 아는 상태**에서 생성했다. 정답의 직전 속도·방향이나 미래 경로는 입력하지 않았다.
- 학습 모델, 일정 속도·방향 모델, 정지 모델을 비교했다. 시점마다 독립 표본 32,768개 두 묶음을 사용했으며 시드를 바꾼 전체 반복도 수행했다.
- 위치 분포의 에너지 점수는 `E|X−y| − ½E|X−X′|`로 계산했다. 작은 값이 좋다. 이는 위치 오차나 발견률 자체가 아니다. [평가식 근거: Pic 외, ASCMO 2025, 식 12](https://ascmo.copernicus.org/articles/11/23/2025/index.html).

## 결과: 시간이 길어지면 확률 표현의 신뢰성이 달라진다

| 경과 시간 | 모델 80% 분위수 반경 | 실제 도착점 포함률¹ | 학습 모델 분포 점수 | 일정 속도·방향 점수 | 정지 점수 |
|---|---:|---:|---:|---:|---:|
| 30초 | 43.1 m | 95.9% | 17.37 | 17.31 | 23.20 |
| 2분 | 140.8 m | 83.4% | 61.05 | 62.32 | 79.75 |
| 5분 | 287.5 m | 72.6% | 135.31 | 141.59 | 172.69 |

¹ 사람별 포함률을 먼저 구한 뒤 동일 가중치로 평균했다. 전체 214구간을 합친 포함률과 다를 수 있다. 이산 속도 대표값 때문에 분위수 반경의 예측 질량이 정확히 80%일 필요도 없다. 특히 30초는 이산값의 영향이 크다. 생성 반경은 검증된 신뢰구간이나 POD가 아니다.

5분에는 학습 모델의 평균 점수가 일정 속도·방향 기준보다 6.28 낮았다. 그러나 사람 단위 2,000회 재표집의 차이 범위가 **−0.25~+13.33**으로 0을 포함한다. 평균 개선만으로 우월하다고 결론내릴 수 없다. 2분도 차이 범위 **−0.09~+2.74**로 0을 포함했다.

시드를 바꿔 다시 계산했을 때 세 모델의 순서는 유지됐다. 5분 학습 모델의 평균 점수 변화는 0.32, 실제 포함률은 72.6%→72.4%였다. Monte Carlo 오차가 전혀 없다는 뜻이 아니며 특히 30초 모델 간 점수 차이는 작다. 경로 생성 코드를 평가와 웹 화면이 공유하도록 정리했고, 기존 시드 42의 0/30/120/300초 응답이 변경 전과 바이트 단위 해시까지 같은지 검사했다.

## 데이터에서 확인한 문제

동일 보행 라벨 안에서 비증가 시각 237,180쌍을 분해했다.

- 같은 시각·같은 좌표: **39,170쌍**.
- 같은 시각·다른 좌표: **198,010쌍**.
- 시간 역행: 0쌍.

다른 좌표가 나온 198,010쌍의 숫자형 시각과 날짜·시간 문자열을 모두 대조했다(비교 396,020회). 1초 초과 불일치는 0회였고, 두 기록의 문자열 시각 역시 모두 같았다. 숫자형 날짜만 잘못 읽어서 생긴 문제는 아니었다.

이 사실이 모든 좌표가 틀렸음을 뜻하지 않는다. 1초 미만 측정이 같은 초로 기록된 경우나 다른 기록 효과일 수 있으나, 근거 없이 시각을 만들어 순서를 복원하지 않았다. 단순 중복만 가진 사람 중 v1에서 제외된 사람은 2명뿐이어서 단순 중복 제거만으로 충분한 새 평가 인원을 확보하기도 어렵다. **v1 원자료·정제 결과·모델을 보존했다.**

## 적용한 변경

[학습 실험실](http://127.0.0.1:8000/?view=walking-lab)에 **시간 누적 예측 평가**를 추가했다. 계산된 반경과 실측 포함률, 평균 개선의 불확실성을 함께 표시한다. 웹에는 집계 결과만 제공하고, 실제 GPS·사람별 창 ID·시각은 제공하지 않는다. 평가 파일이 변조됐거나 모델 버전과 맞지 않으면 수치를 표시하지 않는다.

기존 실종자 지도·학습된 수색대 속도·YOSAR 끝점 모델·임무 기록은 교체하지 않았다. **NOT_ADOPTED 판정을 유지**한다. 이번 자료는 일반 보행이며, 같은 5명의 후속 검사다. 국내 실종자 행동, 지형·야간·시설 효과, 수색 탐지확률, 실제 현장 효용은 여전히 검증 전이다.

## 증거와 재현

- `data/ml/geolife/duplicate_audit.json`: 같은 시각의 중복/충돌 감사.
- `data/ml/geolife/conflict_time_check.json`: 충돌 기록의 두 시각 필드 대조.
- `data/ml/geolife/horizon_evaluation.json`: 시점별·사람별 결과, 시드 반복, 창 식별자(로컬 전용).
- `data/ml/geolife/horizon_receipt.json`: 모델·원자료·정제 자료·프로토콜·계산 코드 해시.
- `artifacts/geolife-horizon-mobile.png`: 앱의 실제 모바일 표시.

실행한 계산:

```sh
.venv/bin/python -m pipeline.audit_geolife_duplicates
.venv/bin/python -m pipeline.check_geolife_conflict_times
.venv/bin/python -m pipeline.evaluate_geolife_horizons
.venv/bin/python -m pytest backend/tests -q
```

산출물이 이미 있으면 평가 코드는 덮어쓰지 않고 중단한다. 검사 결과는 백엔드 **98개 통과**, 프런트 빌드 및 `walking-check.mjs`의 모바일·수치 표시·시간/시드 변경·임무 보존 성공이다. 빌드의 기존 대형 번들 경고는 남는다. 성능 평가 통과와 기능 검사 통과는 별개다.

## 목표의 남은 부분

“실제로 작동하는 AI”의 계산·저장·앱 실행은 있으나, **학습된 시간별 실종자 존재확률로 현장 수색 범위를 결정하는 완성 상태는 아직 아니다.** 그 주장을 하려면 대상 유형·지역에 맞는 관측 자료와 독립 수색 평가가 더 필요하다. 공모전·모의 수색에서의 동작 완성과 현장 투입은 다른 완료 기준이므로 사용자에게 적용 범위를 확인 요청했다. 답변이 오기 전에는 안전성을 임의로 보증하거나 목표 전체를 완료 처리하지 않는다.
