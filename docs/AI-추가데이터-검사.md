# 추가 보행 자료: 전 파일 검사와 학습 판정

검사일: 2026-09-19. **새 보행 자료 165개를 모두 읽었지만, 확인되지 않은 시간 단위를 정답으로 바꾸어 학습하지 않았다.** 기존 발견 거리·수색대 속도 학습 모델은 유지했다. 데이터 탐색·통계 분석 절차에 따라 원자료, 단위, 관측의 독립성, 예측 시점에 알 수 있는 입력을 각각 검사했다.

## 1. 실제 파일에서 확인한 내용

출처는 Cutler, Campbell, Dennison의 [Mobile Lidar Scanner Trajectories](https://zenodo.org/records/17081136), CC BY 4.0이다. 원래 수집 manifest·원본 ZIP은 수정하지 않았다. 새 `quality_report.json`에는 원본 및 검사 코드의 SHA-256, 의존성 버전, 전 파일별 결과를 남겼다.

| 항목 | 전수 검사 결과 |
|---|---|
| LAS 파일 / 관측점 / 인접 구간 | 165 / 39,962 / 39,797 |
| 형식 | 모두 LAS 1.2, point-format 0 |
| 좌표계 | 모두 EPSG:26912, 수평 좌표 단위 metre |
| 원본 바이트가 동일한 중복 파일 | 0개. 관측·사람·사건 독립성이 입증됐다는 뜻은 아님 |
| 수치 필드 비유한 값 | 검사한 모든 수치 필드에서 0개 |
| 파일명 토큰 | 코스 모양 토큰 11종, 문자 토큰 A–I 9종, up 82 / down 83 |
| OffsetTime 인접 차이 | 39,797개 모두 1 |
| GpsTime 인접 차이 | 0인 구간 39,480개, 128인 구간 317개 |
| 학습용 속도 라벨 출력 | 0개 |

파일명은 `t4aA_up.las.las` 같은 형식이다. `4a`, `A`, `up`을 분리할 수는 있지만 코스·사람 대응 사전은 확인하지 못했다. **9종 문자 = 검증된 9명 식별자**로 확정하거나, 파일 수를 실종 사건 수로 세지 않는다. 점 단위 무작위 학습/평가 분할도 하지 않는다.

연결 [2026 논문](https://doi.org/10.1080/15481603.2026.2626632)은 분석 표본과 시간 간격 처리 과정을 별도로 설명한다. 이 ZIP의 점 수와 분석 표본이 동일하다는 증거는 없다. 논문의 성능을 우리 모델의 성능으로 인용하지 않는다.

## 2. 시간 단위 문제

LAS의 `OffsetTime` 설명에는 밀리초가 기재되어 있다. 그러나 이 값을 그대로 밀리초로 계산하는 것과 `GpsTime`이 시사하는 시간 차이가 맞지 않는다. `GpsTime`도 연속적인 초 단위 정밀 관측이 아니라 0 또는 128씩 변한다.

반올림을 **가정한 진단**도 수행했다. `GpsTime`이 초 단위이고 각 점의 반올림 오차가 최대 64초이며, 실제 시간이 `상수 + k × OffsetTime`이라면, 점 쌍마다 다음 필요조건이 생긴다.

```text
(ΔGpsTime − 128) / ΔOffsetTime ≤ k ≤ (ΔGpsTime + 128) / ΔOffsetTime
```

전 파일 내 유효 점 쌍 7,086,965개에 대한 공통 범위는 약 **0.998885 ≤ k ≤ 1.001117**이다. 이 가정 아래에서는 1초/단위가 들어가고 0.001초/단위는 들어가지 않는다.

하지만 이는 반올림 가정에 의존하는 일관성 진단이다. **통계적 신뢰구간도, 시간 단위가 초라는 확증도 아니다.** 실제 반올림 원인·GPS 시간 기준·내보내기 코드를 확인하기 전에는 필드 설명을 임의로 바꾸지 않는다. 시간 단위를 잘못 읽으면 속도 라벨이 1,000배 달라질 수 있다.

## 3. 시간이 해결돼도 필요한 것

1. 저자 또는 처리 코드로 시간 단위·시간 기준·내보내기 정밀도를 확인한다.
2. 파일↔참가자↔코스 대응표와 논문 분석에 포함한 파일 목록을 확보한다.
3. 이동 기록과 독립적인 DEM·식생 밀도·거칠기 자료를 확보한다. 관측 이후의 궤적에서 계산한 경사를, 예측 전에 알고 있는 지형 입력으로 바꾸어 부르지 않는다.
4. 사람 및 코스를 분리하는 검증을 먼저 고정한다. 일반 보행 속도 성분의 검증이지 실종자의 방향 선택·시설 방문·POD 검증은 아니다.

이 조건들은 `quality_report.json`의 네 가지 gate에 실패 사유와 함께 기록된다. 현재 원자료에서 라벨을 출력하는 경로 자체가 없고, 웹앱의 학습 모델을 교체하지 않는다.

## 4. 대체 자료의 실제 접근 상태

| 자료 | 확인한 상태 | 이번 처리 |
|---|---|---|
| [STRIDE 연구, 2024](https://www.nature.com/articles/s41598-024-71359-6) | 논문은 원자료를 교신저자 요청으로 제공한다고 명시 | 확보·학습했다고 표시하지 않음. 외부 연락을 보내지 않음 |
| [저자의 STRIDE 저장소](https://github.com/mickeycampbell/stride) | 지형 기반 보행 시간 계산 R 구현·설명서. 검사한 저장소 트리에 원 실험의 학습 표는 없음 | 외부 코드를 실행하거나, 기존 계수를 우리 재학습 결과로 포장하지 않음 |
| [UK hiking 연구, 2023](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0295848) | GPS 출처·처리 코드는 공개 안내되나, 결합 학습 자료의 직접 공유는 지형 자료 이용 조건으로 제한 | 논문이 공개됐다는 이유로 완성 학습 자료를 확보했다고 판단하지 않음 |

위 대체 자료도 실제 실종자의 시각별 이동·시설 선택·미발견/발견 정답을 제공한다고 확인한 것은 아니다. 공개 보행 연구만 추가하면 원래 목표가 전부 달성된다는 주장을 하지 않는다.

## 5. 재현과 보존

학습 전용 환경에서 프로젝트 루트를 기준으로 실행한다.

```sh
.venv-ml/bin/python -m pipeline.profile_offtrail
.venv/bin/python -m pytest backend/tests/test_offtrail_profile.py backend/tests/test_research_qa.py -q
```

의존성은 `pipeline/offtrail-requirements.lock`에 고정했다. 웹앱 환경에는 LAS 해석 라이브러리가 필요 없다. 원본·manifest 해시가 달라지면 파일 읽기/보고서 생성을 거절한다. 속도 변환 오류의 반례는 합성 단위 테스트에서만 사용하며 학습 데이터나 모델에 넣지 않는다.

산출물은 `data/research/offtrail_lidar_2025/quality_report.json`이다. 원본 파일별 통계 및 검사 코드 해시로 재검사할 수 있다. 이 보고서는 새로운 데이터 품질 근거이며 현장 발견 성능·모델 정확도 평가 결과가 아니다.
