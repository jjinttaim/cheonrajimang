# 생성형 AI 활용 공개문

공모전 제출물에 첨부하거나 발표 슬라이드 마지막 장에 요약해 넣기 위한 문서다. 대괄호 항목은 팀이 채운다. 사실과 다르게 축소하거나 부풀리지 않는다 — 심사위원이 코드 한 줄을 가리키며 "이건 누가 왜 이렇게 했나요"라고 물었을 때 답할 수 있는 범위가 곧 팀의 기여다.

## 2. 팀이 직접 한 것

- 문제 정의: 2026년 8월 제주 실종 사건을 계기로 "민간 수색은 이루어지지만 증명되지 않는다"는 문제를 정하고, 조정자·봉사자·가족의 역할 경계를 설계했다.
- 방향 결정: 선행 서비스 조사(SAROS, FindSquad, 국내 CCTV·안심귀가 앱)를 근거로 두 개의 초기 아이디어(노동권 도우미, 보행 안전 내비게이션)를 포기하고 이 주제로 수렴했다.
- 데이터 선택과 이용 조건 판단: 실제 실종 사건 65건, 수색대 GPS 61트랙, YOSAR, GeoLife 등 각 자료의 이용 조건을 확인하고 학습에 쓸 것과 격리할 것을 정했다.
- 채택 기준 사전 선언: 모델을 학습하기 전에 통과 기준을 문서로 고정하고, 결과가 기준에 미달한 두 모델을 미채택으로 남기기로 결정했다.
- 설계 원칙: 승인된 미발견 기록만 지도에 반영, 단서는 장부에만 기록, 낮은 확률은 부재의 증거가 아님, 지도 밖 잔여확률 상시 표시.
- 검증 실행과 확인: [예: 자동 테스트 실행, 브라우저 검사, 실행 화면 확인, 수치 재계산] — 실제로 무엇을 눈으로 확인했는지 적는다.
- 명칭·브랜드: '천라지망' 명칭과 로고 결정.

## 3. AI가 만든 것에 대해 팀이 확인한 방법

- 백엔드 자동 테스트 114개, 프런트 단위 테스트 14개, Playwright 브라우저 시나리오 검사를 팀 컴퓨터에서 실행해 통과를 확인했다. [실행 날짜·담당자]
- 핵심 수식(lognormal 적합, Tobler 함수, POD = 1−e^(−C), Bayes 갱신, 기하평균 합의, Dijkstra)의 의미와 출처를 `docs/기술-QnA-대비.md`로 정리하고 팀원 전원이 설명할 수 있도록 학습했다. [학습 확인 날짜]
- 학습 결과 수치(NLL 8.877, 80% 반경 포함률 72.3%, 속도 MAE 0.253 m/s 등)는 `models/<묶음>/evaluation.json`에서 직접 읽어 문서와 대조했다.
- 데이터 출처·라이선스는 각 `NOTICE.md`와 `LICENSES.md`로 대조했다.

## 5. 남아 있는 책임

이 프로젝트의 코드와 문서에 오류가 있다면 그 책임은 도구가 아니라 팀에게 있다. 팀은 제출 전에 다음을 다시 확인한다.

- [ ] 기획서의 모든 수치가 실행 중인 프로그램·평가 파일과 일치하는가
- [ ] 화면과 보고서의 "검증 전", "가정", "미채택" 표시가 지워지지 않았는가
- [ ] 실제 실종자 개인정보를 어떤 파일에도 넣지 않았는가
- [ ] 데이터 이용 조건(비상업 자료)을 제출물에서 위반하지 않았는가
